# MCP-сервисы AppFactory

Три независимых сервиса. Каждый — один Docker-контейнер, отдающий функции
(tools) по протоколу Model Context Protocol (MCP) через транспорт
`streamable-http` на пути `/mcp`. Вместе закрывают цепочку «грязный CSV →
норма → эталоны → расписание» для строительных проектов.

| MCP | Папка | Порт наружу | Что делает |
|-----|-------|-------------|-----------|
| csv | `mcp/csv/` | `127.0.0.1:18081` | Нормализует CSV, умеет цикл «скачать → нормализовать → выгрузить в S3» |
| planning | `mcp/planning/` | `127.0.0.1:18082` | Строит расписание по CSV работ (движок SAMPO, Python 3.10) |
| semantic-mapping | `mcp/semantic-mapping/` | `127.0.0.1:18080` | Сопоставляет грязные названия с эталонами (TEI + pgvector), только чтение |

Подробно по каждому — свой README: структура, настройка, обновление,
сценарии, проверка.

Внутри каждого пакета четыре слоя: `sources/` (неизменённый снимок чужого
исходного кода) → `src/stairs_*` (рабочий срез этого кода) → `src/*_adapter/`
(наши границы: валидация, безопасность) → `src/*_mcp/` (тонкий транспорт).
Правило: `sources/` и срезы руками не править (исключения описаны в README
пакетов); вся наша логика — в `*_adapter`.

## Откуда что взято

Приватных URL в репозитории нет: `sources/SOURCES.md` каждого пакета фиксирует
локальный снимок + коммит. Доноры: `stairs-backend` (csv — 1 файл, planning —
оценка работ), `stairs-resource-model` и `stairs-storage` (planning, целиком),
`stairs-semantic-mapping` (целиком, 9 файлов 1-в-1). Внешние зависимости:
`mcp[cli]==1.16.0`, `pydantic==2.11.9` (пины везде), `sampo==0.1.2.0.6`
(только planning). Остальное — в `requirements.txt` пакетов.

## Обновление при изменении исходника

Общее правило: перекопировать снимок в `sources/` → обновить хеш в
`sources/SOURCES.md` → обновить рабочий срез → прогнать тесты-гейты пакета.
`.env`, тесты и `pyproject` исходников не копировать; зависимости — только из
своего `requirements.txt`. Пошагово для каждого пакета — в его README.

После любого обновления: хеши сходятся; гейт пакета зелёный; порты не
менялись (внутри `8080/mcp`); секреты только в env, не в образе/логах.
